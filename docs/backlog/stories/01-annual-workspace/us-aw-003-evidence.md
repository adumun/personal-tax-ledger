# PTL-US-AW-003 — Initialize from Prior Year — Evidence

**Type:** Story  
**Capability:** TAX-01  
**Priority:** P1  
**Status:** IN_REVIEW  
**Date:** 2026-09-13  
**Branch:** `feat/block-01-prior-year-initialization`

## User outcome implemented

The `Crear año tributario` flow now offers an explicit `Inicializar desde un año anterior` mode with source-year selection, category preview, optional category selection and mandatory communication of what will not be copied.

## Acceptance evidence

### AC-01 — preview before confirmation

The modal shows:

- source year;
- reusable categories and availability;
- selected categories;
- mandatory `No se copiarán` section.

### AC-02 — copied configuration is not a realized tax fact

The only Block 01 reusable category is `APPLICABILITY_PROFILE`, copied as a revisable proposal. No income source, BHE, retention, PPM, mortgage, evidence or result is generated by initialization.

### AC-03 — provenance

Every successful initialization persists source workspace/year, target workspace/year, actual category set and initialization timestamp in `annual_workspace_initializations`.

### AC-04 — optional category selection

The user can uncheck an available category before executing. Unsupported/unavailable categories are not silently enabled.

### AC-05 — partial failure does not declare success

If reusable-data or provenance persistence fails after target creation, the target workspace is removed and the previously active year is restored.

### AC-06 — repeat is idempotent

Re-running the identical source/target/category initialization returns the persisted provenance with `alreadyInitialized = true`. Different provenance against an existing target remains an explicit conflict.

## UX contract

The implementation follows `DESIGN-AW-003`:

```text
Inicializar desde año anterior
  Año fuente
  Reutilizar
    [x] Perfil de aplicabilidad como propuesta
  No se copiarán
    • montos realizados / ledger
    • boletas / retenciones / PPM
    • evidencia / conciliaciones
    • readiness / cierre
    • resultados / proyecciones
```

The generic `Configuraciones reutilizables compatibles` and recurring-source templates are intentionally not enabled yet because no canonical reusable-configuration classification/template model currently makes them safe.

## HTTP/UI

Endpoint:

```text
GET  /api/annual-workspace/prior-year-initialization?sourceCommercialYear=...&targetCommercialYear=...
POST /api/annual-workspace/prior-year-initialization
```

The new target is activated only through the canonical AW-002 workspace flow; the initializer does not create a second year-activation mechanism.
